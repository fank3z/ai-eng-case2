# Changelog промптів

## rag v2 — 2026-11-22
**Що змінено порівняно з v1**
- Явна заборона знань «від себе» і правило not_found навіть для дотичної інформації.
- Правила для скасованих версій документів і для суперечностей між джерелами.
- Вимога атомарних тверджень (claims) з посиланням лише на джерело, де факт прямо написаний.
- Точне перенесення чисел/кодів, обмеження довжини відповіді.

**Чому:** без правил модель могла б відповідати поза корпусом, брати значення зі скасованих версій і ставити цитати «в кінці абзацу», що унеможливлює перевірку faithfulness.

**Результат (факт, основна конфігурація, 26 питань)**
| Метрика | v1 | v2 |
|---|---|---|
| «Не знаю» де треба | 1.00 | 1.00 |
| Ключові факти | 1.00 | 1.00 |
| Точність цитат | 0.98 | 1.00 |
| Faithfulness (judge_faithfulness v2) | 1.00 | 1.00 |
| Latency p50, с | 1.09 | 2.58 |

**Висновок:** на поточному тестсеті v2 не має вимірюваної переваги за якістю і повільніший. Лишено основним через правила для скасованих версій: в ablation без фільтра `status` (q02) модель на v2 сама позначила старе значення як скасоване.

## rag v1 — 2026-11-22
Baseline: коротка інструкція «відповідай за джерелами, цитуй S1…, not_found якщо немає».

## judge_faithfulness v2 — 2026-11-23
**Що змінено:** судді пояснено формат контексту (заголовок джерела з версією і статусом) і правило: факт належить тій версії документа, під заголовком якої написаний. Одночасно в коді eval контекст для судді тепер передається з заголовками джерел.
**Чому:** на v1 суддя забраковував правильну відповідь q26 («у версії 1 TAC був 41001»), бо не відрізняв таблиці версій 1 і 2 настанови NB-IoT.
**Результат:** faithfulness основної конфігурації 0.98 / 0.95 (v1 / v2) → 1.00 / 1.00; в ablation 0.87 → 0.93 (лишилось одне непідтверджене твердження — q09, неточно переписана назва аварії).

## judge_correctness v1 — 2026-11-22
